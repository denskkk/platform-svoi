# Дорожная карта: «Свій для Своїх» как социальная сеть-экосистема

Ветка: `feature/social-feed`. Принципы (неизменные): не ломать существующее (авторизация, данные), только аддитивные миграции, весь текст в uk+en, каждая кнопка делает реальное действие, всё работает в Capacitor-приложении, ничего в `main` и никакого деплоя без явного «да».
Модель: **бесплатная**, без платных подписок и тарифов. Тип аккаунта (basic/business/viewer) — только уровень доступа.

> Примечание: полный текст ТЗ в этой сессии сжат до выжимки; пункты ниже сверены с ней. Если в оригинале ТЗ есть пункт, которого тут нет, — добавить в раздел «Сверка с ТЗ» ниже.

## 0. Что уже сделано (кратко)
Лента (посты, фото, лайки, комментарии, ответы и лайки комментариев, подписки, закладки, блокировки, жалобы, уведомления), «Друзі», рекомендации, единый поиск, оголошення (Авто/Нерухомість) с модерацией, заявка бизнеса, «Як заробити з нами?» + партнёрские заявки, роли персонала, упрощённая регистрация (одна форма → сразу лента), оформление как Facebook (верхняя панель, чат как Messenger, 3 колонки ленты), страница «Видео» (Скоро).

## 1. Блок A — Довести «ядро соцсети» до идеала (ближайшие 1–2 недели)
Цель: чтобы привычные действия ощущались как в Facebook и не лагали.

| # | Задача | Что менять | Готово, когда |
|---|---|---|---|
| A1 | Скорость | `/uploads` напрямую через nginx; убрать лишнее из клиентского бандла; проверить тяжёлые запросы (`/api/feed`, `/api/recommendations`) на N+1 и индексы; пагинация везде | Лента открывается < 1 с на prod-сборке; Lighthouse mobile ≥ 80 |
| A2 | Реакции и репосты | Реакции (👍❤️😂😮😢) вместо одного лайка: таблица `post_reactions` (аддитивно), UI long-press/hover; «Поделиться» внутри платформы (репост с подписью) | Реакция меняется/снимается, счётчики верные, уведомление автору |
| A3 | Упоминания и хэштеги | `@имя` (уведомление), `#тег` → страница тега | Клик по тегу ведёт на список постов |
| A4 | Редактор поста | Эмодзи, опрос (poll), место/город, видимость (все / подписчики) | Видимость реально фильтрует ленту и профиль |
| A5 | Профиль как в Facebook | Обложка + аватар, вкладки (Публикации / О себе / Фото / Друзья / Отзывы / Услуги), кнопки «Написать», «Подписаться» | Все вкладки с реальными данными |
| A6 | Мессенджер | Статус «прочитано», индикатор набора (polling), вложения-фото, удаление сообщения, поиск по чатам | Работает в Capacitor, клавиатура не перекрывает поле |
| A7 | Уведомления | Группировка, «прочитать всё», настройки (что присылать) | Бейдж совпадает со списком |
| A8 | Push | FCM/APNs через Capacitor Push Notifications | Нужно обновление в сторах — **согласовать отдельно** |
| A9 | Онбординг | После регистрации: выбрать город, интересы (направления), подписаться на 5 рекомендованных | Лента не пустая с первой минуты |

## 2. Блок B — Видео и истории (после данных по VPS)
Решения: хранение на диске VPS, отдача **nginx** напрямую (Range, кэш); без серверной перекодировки; лимит ≤ 60 с и ≤ 40 МБ, mp4/webm; превью-кадр делает клиент; потоковая загрузка отдельным маршрутом (не через formData в памяти); лимит загрузок в сутки на человека.
- B1 Видео в постах (поле video в `post_images`/новая `post_videos`), плеер `preload="none"`, автоплей без звука в зоне видимости.
- B2 Истории на 24 ч (`stories`, `story_views`), удаление по cron раз в сутки, кольцо над аватаром в ленте.
- B3 Раздел `/video` (лента коротких видео).
- B4 Запасной путь: перенос файлов в Cloudflare R2 при нехватке диска.
**Нужно от владельца:** свободное место на диске, ядра/ОЗУ, есть ли nginx на VPS и путь к `UPLOADS_DIR`.

## 3. Блок C — Экосистема направлений (из ТЗ)
Платформа = единая сеть + направления («проекты»). Уже есть: Авто, Недвижимость. Остальные направления из ТЗ — по очереди, каждое по шаблону:
`направление → объявления/витрины → заявки → модерация → страница «Як заробити з нами?»`.
- C1 Универсальный каркас направлений (категории, поля-расширения, фильтры) — чтобы новые направления не требовали нового кода: таблица `project_fields` (аддитивно).
- C2 Направления: здоровье, спорт, торговля/магазины, услуги, мероприятия, клубы/сообщества.
- C3 Витрины бизнеса (страница компании: каталог, часы работы, контакты, отзывы, QR на витрину).
- C4 События (дата/место, «пойду/интересуюсь», напоминание) и клубы/группы (участники, посты внутри группы).
- C5 Отзывы и рейтинг везде единые (уже есть для услуг → расширить на бизнес/объявления).

## 4. Блок D — Рефералы, сделки, комиссии (требует решений владельца)
Только каркас и честные статусы, **без выплат**, пока нет юр. условий:
- D1 Реферальная ссылка/код пользователя, учёт переходов и регистраций.
- D2 «Сделка» (deal): заявка → подтверждение сторонами → статус; ожидаемая комиссия как **предложение**, не гарантия.
- D3 Баланс/начисления — только после юр. условий и платёжного провайдера; до тех пор раздел «Скоро».
- D4 QR/NFC/POS — стадия исследования (сначала QR-ссылки на витрины/профили).
**Нужно решить:** юр. форма, условия реферальной программы, платёжный провайдер, налоги.

## 5. Блок E — Модерация, безопасность, качество
- E1 Панель модератора (жалобы на посты/комментарии/сообщения; скрыть, предупредить, забанить) — расширить `/admin/staff`.
- E2 Антиспам: лимиты, дубли, ссылки от новых аккаунтов, подтверждение e-mail.
- E3 Политика контента и согласия (Terms/Privacy) под сторы: удаление аккаунта уже есть; экспорт данных.
- E4 Логи аудита на все админ-действия (есть для части) — довести до 100%.
- E5 Тесты: добавить smoke-тесты API (`feed`, `friends`, `comments`), прогон `npm run test:i18n`.

## 6. Блок F — Выпуск
1. Применить миграции одним проходом `database/apply_social_update.sh`.
2. `npm ci && npx prisma generate && npm run build` — исправить ошибки типов (в моей среде `.tsx` не проверяется).
3. Ручной прогон по чек-листу (регистрация → лента → пост → комментарий/ответ → подписка → чат → поиск → оголошення → заявка бизнеса).
4. Тест в Capacitor: safe-area, клавиатура, выбор фото, оффлайн.
5. Pull Request `feature/social-feed` → ревью → **деплой только по явному «да»**.

## 7. Порядок ближайших шагов
1. A1 (скорость) → A5 (профиль) → A2 (реакции/репосты) → A9 (онбординг) → A6/A7.
2. После данных по VPS: B1 → B2.
3. C1 каркас → по одному направлению за итерацию.
4. D1 (рефералы без выплат) после решения владельца.
5. После каждого шага: миграция (если есть) отдельным файлом, обновление `apply_social_update.sh`, i18n uk+en, запись сюда.
